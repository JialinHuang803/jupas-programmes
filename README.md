## 搜尋與使用

可使用簡體、繁體或混合中文搜尋課程名稱、中文速覽及院校名稱，亦支援英文名稱、課程縮寫或 JS 編號，不分英文字母大小寫。
搜尋時會使用本地 OpenCC 字典將關鍵字與課程索引統一為簡體，例如 `计算机` 和 `計算機`、`护理` 和 `護理` 得到相同結果。
轉換只用於搜尋，不修改畫面顯示的官方名稱、摘要、網址中的原始關鍵字或原始 JSON。
這是繁簡文字匹配，不是任意同義詞或跨地區專業術語的語意搜尋。
以空格分隔的關鍵字會取交集；例如 `business management`。
可同時使用院校與資助類別篩選，檢視結果數量、清空篩選，以及每次載入 24 個結果。
所有課程都在快照內；分批顯示只為減少初次頁面負擔，不會截斷收錄範圍。
鍵盤按 `/` 聚焦搜尋，Tab 可切換控制項及官方連結。
支援手機排版、減少動態效果偏好、載入失敗重試、無結果狀態及螢幕閱讀器結果提示。
搜尋篩選保存在網址參數，可複製網址分享；不使用瀏覽器本機持久儲存。

### 官方入學門檻篩選

提供中文、英文及數學必修部分三個固定下拉選單，均預設為「不限」，不使用新增條件或 AND 條件編輯器。
各科可獨立選擇最低門檻；未選「不限」的科目與關鍵字、院校及資助類別一起篩選，課程須符合所有已選門檻。
公民與社會發展科及選修科不提供篩選，但仍在卡片中保留完整官方表格。
這是篩選**課程規定的最低門檻**，不是輸入申請人成績：選擇 `CHINESE LANGUAGE ≥ 3` 會包含官方中文要求 3、4 或更高的課程，而非只找出中文成績 3 能申請的課程。
數字級別按照 `1 < 2 < 3 < 4 < 5 < 5* < 5**` 比較；卡片中的 `Attained` 等非數字要求原樣保留，不會臆測成數字級別。
「重設為不限」只清除這三科的門檻，保留關鍵字及院校；「清空篩選」則重設所有篩選。
網址可保存並還原三科的選擇；不支援或重複的科目條件會顯示提示，不會悄悄套用部分門檻。

卡片的官方 OR 與 one-of／two-of 選項保留為結構化路線，不把不同替代路線拼接起來。
`ANY 2 SUBJECTS` 不會從兩條不同限制的 `ANY 1 SUBJECT` 推算出來，指定科目、排除應用學習或其他語言等限制也不會被抹去。
無可結構化表格的課程會明確標示並連到官方頁面；未設定門檻條件時仍收錄，設定條件時不推測其門檻。

**數值篩選不是完整資格判定，更不是錄取保證。**
卡片保留表格的備註編號並提供官方備註連結；長篇文字要求、豁免、作品集、面試、重考與計分規則等不納入數值匹配，仍須閱讀官方詳情。
原始官方英文科目標籤與最低級別保留，中文只解釋結構及篩選操作。

## 本機啟動與驗證

需要 Node.js 22 或更新版本。

```powershell
npm ci
npm test
npm start
```

開啟 <http://127.0.0.1:4173/jupas-programmes/>，直接用 `file:` 開啟 HTML 無法載入資料。
本機伺服器僅綁定 `127.0.0.1`，供開發預覽使用。
`npm ci` 的 prepare 步驟會將固定版本的 OpenCC 繁轉簡模組及授權聲明複製至忽略版本控制的 `assets/vendor`，瀏覽器從本站載入，不使用 CDN。
如需重新準備此靜態資產，可執行 `npm run prepare`。

```powershell
npm run build
```

將 HTML、靜態資產與資料複製至忽略版本控制的 `dist`，不包含 Git、測試或採集腳本。
所有資產和 JSON 使用相對路徑，適用 GitHub Pages 的儲存庫子路徑。
單元測試涵蓋 345 筆資料完整性、八校數量、每筆中英文搜尋、全量名稱及摘要的繁簡搜尋等價性、混合字體、摘要一致性、官方連結、篩選交集及官方 HTML 解析異常。
入學要求測試使用由官方頁面擷取的純表格樣本，涵蓋課程／一般要求的區分、跨 OR 路線的錯誤拼接、one-of／two-of 選項、任選科目排除限制及非數字級別。

## 更新資料

```powershell
npm run update-data
npm test
```

採集腳本檢查 `robots.txt`，若不存在（404）則繼續；如出現限制性規則則停止，要求人工核對，不嘗試繞過。
`npm run update-data` 依序讀取官方申請日程、八校完整列表及每個課程的入學要求區段（目前 345 頁）；請求間隔至少 1.5 秒，不使用並行請求或全站抓取。
只解析入學門檻表格及備註編號，不將官方完整課程簡介或長篇文字備註複製到公開資料。
完整更新通常需要十多分鐘；如只需更新目前快照的入學要求，可執行以下命令：

```powershell
npm run update-requirements -- --cache-dir "$env:TEMP\jupas-requirements-cache"
npm test
```

快取保存在指定的本機目錄，不納入網站或儲存庫；僅重用同一入學年度、同一官方連結且 24 小時內的內容，方便失敗後重新執行，避免反覆下載已成功的頁面。
完整更新也支援 `npm run update-data -- --cache-dir "$env:TEMP\jupas-requirements-cache"`。
未指定快取目錄時，每次均重新依序讀取官方頁面。
資料失敗、官方結構改變、中文名稱缺失、重複編號、無法核對入學年度、列表中有未解析編號，或入學表格出現未識別的邏輯與不完整欄位時，明確報錯並保留原 JSON。
中文名稱缺失時需維護者先人工審閱翻譯，不生成虛構替代資料。
成功後才原子替換 `data/programmes.json`。
更新後應核對資料差異、摘要及官方來源；若官方年度或課程數量改變，需同步更新本 README 和測試內當期快照預期。
確認無誤後再提交與推送，不設自動採集或定時部署。

## GitHub Pages 部署

儲存庫的 **Settings → Pages → Build and deployment → Source** 使用 **GitHub Actions**。
`.github/workflows/pages.yml` 在推送 `main` 或手動觸發時安裝鎖定的依賴並準備本地轉換字典、執行測試、準備靜態檔案，再透過官方 `configure-pages`、`upload-pages-artifact` 及 `deploy-pages` 發布。
失敗的驗證不會進入部署。
不需要 PR、API 密鑰、自訂伺服器或付費服務。
